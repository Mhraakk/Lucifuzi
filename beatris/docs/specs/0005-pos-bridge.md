# 0005 — پرداخت خودکار با کارتخوان (PC-POS)

**وضعیت:** پیاده‌شده؛ روی سخت‌افزار واقعی آزموده نشده (فقط با شبیه‌ساز پروتکل).

## What
وقتی در میز معامله پرداختی با روش «کارتخوان» (دریافت از مشتری) هست و کارتخوانِ این دستگاه فعال است، «ثبت» اول مبلغ را به کارتخوان می‌فرستد؛ سند فقط پس از تأیید بانک ثبت می‌شود و شماره پیگیری (RRN)، چهار رقم آخر کارت و شماره پایانه خودکار روی پرداخت می‌نشیند.

- **پل محلی** `desktop/windows/pos-bridge.ps1` (PowerShell داخلی ویندوز ۱۱، بدون نصب چیز اضافه): سرور HTTP روی `127.0.0.1:8765`، فقط برای origin اپ. همراه نصب‌کننده ویندوز نصب و با ورود به ویندوز اجرا می‌شود.
- **راه‌انداز `sep`**: پروتکل عمومی SSP1126 سامان کیش / پرداخت الکترونیک سامان روی TCP ۱۱۹۷ (ISO-8583 با MTI ‌`0300`، MAC به روش DES-CBC). خرید PC-starter: DE3=`000000`، DE4 مبلغ ریال، DE46=`300`، DE49=`364`، بدون DE63. دنباله: `15` → `000008` (نتیجه) → ACK → `17` → Dispose.
- **راه‌انداز `command`** (برای سداد و هر PSP دیگر): پل برنامه‌ای را که در `pos.json` همان رایانه تعریف شده با مبلغ اجرا می‌کند و JSON خروجی‌اش را می‌خواند. پروتکل سداد عمومی نیست؛ DLL رسمی سداد لازم است.
- **راه‌انداز `sim`**: شبیه‌ساز برای آموزش و آزمون؛ شماره پیگیری با `SIM` شروع می‌شود.
- **سرور**: جدول `bk_pos` و `GET/POST /api/books/pos` — هر تراکنش (موفق، رد، لغو، نامعلوم) با سند متصلش؛ «تأییدشده بی‌سند» برای تطبیق دیده می‌شود.

## Constraints
- تأیید فقط وقتی است که پیام `000008` با MAC درست و DE39=`00` برسد؛ هر حالت دیگر «تأییدنشده».
- مبلغ از محاسبه سند (`calc.payments[i].value`، ریال صحیح) گرفته می‌شود نه از متن ورودی.
- مرورگر هرگز فرمان اجرایی به پل نمی‌دهد؛ راه‌انداز `command` فقط از فایل محلی خوانده می‌شود.
- بدون وابستگی؛ CSP فقط `http://127.0.0.1:*` و `http://localhost:*` را به `connect-src` می‌افزاید.

## Out of scope
- اتصال سریال (COM)؛ فقط شبکه (LAN).
- استرداد / ابطال تراکنش از اپ (روی خود کارتخوان انجام می‌شود).
- پیاده‌سازی پروتکل خصوصی سداد بدون DLL رسمی.

## Verification
`npm run gate` + `E2E_ONLY='pos' npm run e2e` + آزمون پل با `pwsh` (در CI روی ubuntu موجود است).
