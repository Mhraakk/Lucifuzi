# 0039 — یکپارچگی کل اپ: فهم کد با گراف، ظاهر و حرکت یکدست

- **What:** خواست مالک: ابزارهای فهرست‌شده در «فهم و ساخت یکپارچه‌ی اپ» به کار بروند، روی کل اپ. چهار بخش دارد:
  1. **فهم کد با گراف:** CodeGraphContext همه‌ی کد خود اپ را نمایه می‌کند: سرور، صفحه‌ها، اسکریپت‌ها و آزمون‌ها، یعنی ۲۹۵ فایل، ۳۸۹۷ تابع و ۵۱٬۶۱۱ فراخوانی. کد vendor و رسانه بیرون می‌ماند. دو پیوند همیشه سنجیده می‌شود (`scripts/links.mjs` در `npm run check`):
     - هر import نام‌دار، در ماژول مقصد export شده باشد؛
     - هر مسیر `/api` که صفحه‌ها صدا می‌زنند، در سرور مسیری داشته باشد.
  2. **کد مرده:** تابعی حذف می‌شود که دو شرط دارد: در گراف هیچ فراخواننده‌ای ندارد، و نامش هیچ جای دیگر کد نیامده است.
     - **می‌ماند:** callbackهای مرورگر و getterها؛ API عمومی موتورها (`books.mjs`، `acct/coa.mjs`، `studio/units.mjs`، `studio/materials.mjs`، `nurbs.mjs`، `elliott.mjs`) که بخشی از کتابخانه‌ی دامنه است.
     - **حذف می‌شود:** باقی‌مانده‌ی ویژگی‌های بازنشسته و کد محلیِ بی‌استفاده.
     - **پیچیدگی:** عددهای بالا مال کارخانه‌های بسته‌ای است (`registerBooks`، `deskPage`، `makeControl`) که همه‌ی مسیرها یا گرداننده‌ها را در خود دارند. فقط گزارش می‌شوند و بازنویسی نمی‌شوند.
  3. **مهارت‌های طراحی (skill-issue.in):** پیش از نصب، همه‌ی پرونده‌هایشان خوانده می‌شود. فقط راهنمای بی‌خطر نصب می‌شود و چک‌لیست بازبینی صفحه‌ها می‌شود.
  4. **ظاهر و حرکت یکدست:**
     - **توکن‌ها:** حرکت (مدت‌ها و منحنی‌ها) و شکل (گردی، سایه و حلقه‌ی فوکوس) یک بار تعریف می‌شوند. همه‌ی transitionها و animationهای لایه‌های `app.css` از همین توکن‌ها می‌آیند.
     - **الگوهای حرکتی:** هر کدام یک جا تعریف و همه جا یکسان به کار می‌رود: ورود صفحه، ورود فهرست، شمارنده‌ی رقم، اسکلت بارگذاری، پیام کوتاه، دیالوگ و برگه، زبانه‌ی لغزان.
     - **منبع الهام:** 21st.dev، kokonutui، motionin، Inspora و landing.gallery. همه با JS و CSS خالص بازنویسی می‌شوند، نه کامپوننت React.
     - جزئیات پس از بازبینی صفحه‌ها در بند «یافته‌ها» می‌آید.
- **Acceptance:**
  1. `npm run check` پیوندها را می‌سنجد: هر import نام‌دار export شده و هر مسیر `/api` صفحه‌ها در سرور هست.
  2. توابع بند «حذف» دیگر نیستند و `npm run gate` سبز است.
  3. آزمون واحد: هر `transition` و `animation` در `app.css` مدت و منحنی را از توکن‌های حرکت می‌گیرد، جز فهرستی بسته که هر کدام دلیل دارد.
  4. e2e: با «حرکت کمتر»، ورود صفحه، فهرست و دیالوگ بی‌درنگ است (مدت محاسبه‌شده ≤ ۰٫۰۱ ثانیه).
  5. e2e: همه‌ی مسیرها، روی گوشی و رومیزی و در پوسته‌ی روشن و تیره، سرریز افقی و خطای کنسول ندارند.
  6. همه‌ی e2e (۶۴۶ بررسی و بیشتر) و gate سبزند. برگه‌های تصویری همه‌ی صفحه‌ها بازبینی شده‌اند.
- **Constraints:**
  - بدون فریم‌ورک، وابستگی runtime و CDN؛ CSP بدون تغییر (بی‌handler درون‌خطی و بی‌eval)؛ رنگ فقط با توکن.
  - همه‌ی پوسته‌ها (spec 0014)، RTL، و بی letter-spacing روی فارسی.
  - آرام (spec 0006):
    - حرکت رابط حداکثر ۲۴۰ میلی‌ثانیه و ورود صفحه حداکثر ۳۲۰ میلی‌ثانیه؛
    - روی صفحه‌های کاری هیچ پویانمایی بی‌پایان تزئینی نیست، جز «نور زنده» که خاموش‌شدنی است؛
    - فقط transform و opacity؛ همه با `prefers-reduced-motion` خاموش.
  - ساختار DOM و selectorها می‌مانند تا e2e معتبر بماند.
  - منطق حسابداری دست نمی‌خورد.
- **Out of scope:**
  - v0، uxpilot و base44: حساب کاربری مالک را لازم دارند؛
  - کامپوننت‌های React به همان شکل؛
  - ضبط دوباره‌ی ویدیوهای آموزشی: به خواست مالک، ظاهر پیشین را نشان می‌دهند؛
  - تیزر و اینفوگرافیک.
- **Verification:**
  - `npm run gate`؛
  - `npm run e2e`؛
  - برگه‌های تصویری همه‌ی مسیرها در دو پهنا و دو پوسته؛
  - دیپلوی Render و آزمون زنده.
