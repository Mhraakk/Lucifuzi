# 0001 — بیست لایه پلتفرم (تا جایی که به اپ آسیب نزند)

## What
بئاتریس را در ۲۰ لایه معماری کامل کنیم. هر لایه یا (الف) از قبل هست و فقط ثبت می‌شود، (ب) با کمترین تغییر و بدون وابستگی ساخته می‌شود، یا (ج) عمداً ساخته نمی‌شود چون به اپ آسیب می‌زند، و شرط ساختنش در آینده ثبت می‌شود.

## Global constraints (همه لایه‌ها)
- **must:** Node 22؛ `node:sqlite`؛ **بدون وابستگی runtime تازه**.
- **must:** هر تکه با تست واحد تمام شود و `npm run gate` سبز بماند؛ E2E کامل پیش از دیپلوی.
- **do not:** منطق حسابداری، فرمول‌ها، قالب اسناد، شماره‌گذاری یا API موجود را تغییر نده (فقط افزودنی).
- **do not:** ظاهر پوسته‌های تیره را تغییر نده؛ کلید و راز در مخزن نگذار؛ دیتابیس `/data` را جابه‌جا یا حذف نکن.
- **only:** مسیرهای تازه زیر `/api/ops/*` (ارائه‌دهنده) و افزودنی‌های داخلی؛ هر قابلیت ریسک‌دار پشت پرچم (flag).

## Out of scope (آسیب‌زا — ساخته نمی‌شود)
- مهاجرت به Postgres، pgvector، Redis، Kafka/RabbitMQ، فریم‌ورک فرانت جدید: وابستگی و ریسک داده بدون نیاز فعلی.
- امبدینگ برداری با مدل بیرونی: داده مشتری از کشور خارج می‌شود؛ BM25 محلی کافی است.

## Verification
هر فاز: تست واحد تازه + `npm run gate`؛ پایان: E2E کامل، دیپلوی، بررسی زنده با هش فایل و `/api/health?deep=1`.
